# STEPSYNC 서비스 기획서

> **STEPSYNC**  
> **Music for your pace.**
>
> 사용자의 최근 러닝 기록과 목표 페이스를 분석해, 목표 페이스 유지에 도움이 될 가능성이 높은 음악을 AI가 추천하는 반응형 웹서비스.

---

## 1. 문서 목적과 결정 원칙

이 문서는 지금까지의 대화에서 결정된 STEPSYNC의 제품 방향을 정리한다.

### 결정 해석 원칙

- 사용자가 직접 지정한 내용은 확정사항으로 본다.
- 대화 중 제안된 내용 중 사용자가 반박하거나 다른 방향으로 수정하지 않은 내용도 확정사항으로 본다.
- 서로 충돌하는 내용은 사용자의 최신 직접 결정이 우선한다.
- 여러 대안을 동시에 제안했지만 하나를 고르지 않은 경우에는 첫 번째 추천안 또는 가장 강하게 추천한 안을 기본안으로 사용한다.
- 기술적 제약 때문에 아직 실제 제공자를 정할 수 없는 항목은 예외적으로 `추가 결정 필요`로 둔다.

## 2. 제품 정의

### 2.1 서비스명

**STEPSYNC**

- `STEP` + `SYNC`
- 러닝의 발걸음과 음악의 리듬을 맞춘다는 의미

### 2.2 태그라인

**Music for your pace.**

보조 카피로 **Run in rhythm.**을 사용할 수 있다.

### 2.3 서비스 형태

**PC와 모바일 모두에서 사용할 수 있는 반응형 웹서비스**로 만든다.

- 모바일과 PC에서 동일한 핵심 기능을 제공한다.
- 화면 크기와 입력 환경에 맞게 UI를 최적화한다.
- 구현은 **Mobile-first responsive design**을 기본 원칙으로 한다.

### 2.4 핵심 가치

사용자는:

1. 최근 러닝 기록을 입력한다.
2. 원하는 목표 페이스를 입력한다.
3. 음악 취향을 입력한다.
4. OpenAI API가 러닝 기록과 목표 페이스를 분석한다.
5. AI가 사용자에게 적합한 러닝 리듬과 음악 조건을 추론한다.
6. 실제 음악 후보를 검색·검증한다.
7. AI가 후보를 개인 취향과 러닝 목적에 맞게 랭킹한다.
8. 추천 음악 목록과 추천 이유를 보여준다.

### 2.5 서비스가 하지 않는 것

STEPSYNC는 **음악 스트리밍 서비스가 아니다.**

- 음악을 직접 스트리밍하지 않는다.
- 음악 파일을 저장·배포하지 않는다.
- 러닝 중 음악을 실시간으로 변경하지 않는다.
- 실시간 페이스에 따라 음악 재생을 제어하지 않는다.
- Spotify·Apple Music 등의 재생 기능을 대체하지 않는다.

서비스의 핵심 산출물은 **개인화된 추천 음악 목록**이다.

## 3. 문제 정의와 연구 기반 가설

목표 페이스를 정하고 달리더라도 실제 러닝에서는 페이스가 흔들릴 수 있다.

음악의 BPM과 비트는 러닝 케이던스에 영향을 줄 수 있지만, **음악 BPM과 러닝 페이스는 단순한 1:1 관계가 아니다.** 속도는 케이던스와 보폭의 조합으로 만들어지며 개인마다 반응이 다르다.

따라서 STEPSYNC는 단순한 `목표 페이스 → 고정 BPM` 변환기가 아니라 다음을 수행한다.

- 사용자의 실제 러닝 기록에서 페이스·케이던스 관계를 분석한다.
- 목표 페이스를 유지하기 적합한 리듬 범위를 추론한다.
- 사용자의 음악 취향과 실제 곡 메타데이터를 함께 고려한다.
- 평균 페이스뿐 아니라 **Pace Stability(목표 페이스 유지 안정성)**도 중요하게 본다.

제품의 핵심 질문은 다음과 같다.

> **“이 사용자가 원하는 페이스를 가장 안정적으로 유지하는 데 어떤 음악이 도움이 될 가능성이 높은가?”**

## 4. 러닝 기록 입력 방식

러닝 기록 입력 방식은 다음 **3가지로 확정**한다.

1. **서비스 연동**
2. **스크린샷 업로드**
3. **직접 입력**

FIT / TCX / GPX 파일 업로드는 별도 입력 방식으로 추가하지 않는다.

세 방식으로 들어온 데이터는 최종적으로 동일한 내부 러닝 데이터 형식으로 정규화한다.

```text
서비스 연동 ─────┐
                 │
스크린샷 업로드 ─┼─→ 러닝 기록 정규화 ─→ OpenAI API 분석
                 │
직접 입력 ───────┘
```

---

## 5. 입력 방식 상세

### 5.1 서비스 연동

사용자의 러닝 기록을 외부 운동/러닝 서비스에서 자동으로 불러오는 방식이다.

#### 연동 UX

- `러닝 앱 연결하기`를 주요 입력 옵션으로 제공한다.
- 사용자가 권한을 승인하면 최근 러닝 기록을 자동으로 가져온다.
- 기본 분석 대상은 **최근 5회 러닝**으로 한다.
- 장기적으로는 거리와 러닝 유형이 비슷한 기록을 우선 선택해 분석 정확도를 높인다.

#### Samsung Health

사용자는 Samsung Health 연동을 선호하지만, 순수 웹서비스에서 Strava식 OAuth처럼 직접 연결하기 어렵고 Android 앱/SDK 및 배포 제약이 존재한다.

따라서 현재 정책은 다음과 같다.

- **MVP의 직접 Samsung Health 연동은 제외한다.**
- Samsung Health 사용자는 우선 스크린샷 입력으로 지원한다.
- 이후 필요성이 확인되면 Android companion app을 통한 Samsung Health 연동을 검토한다.
- 첫 번째 웹 연동 제공자는 기술 검토 후 별도 선택한다.

> `서비스 연동`이라는 입력 방식 자체는 필수지만, 첫 연동 제공자는 아직 기술 선택이 필요하다.

### 5.2 스크린샷 업로드

Samsung Health, Garmin, Strava 등 러닝/헬스 앱의 기록 화면을 업로드하는 방식이다.

OpenAI의 이미지 이해 기능으로 화면에서 러닝 기록을 추출하고 구조화한다.

#### 필수 UX

AI가 추출한 값은 바로 분석에 사용하지 않고 **사용자가 확인·수정할 수 있는 단계**를 반드시 거친다.

예:

```text
AI가 다음 기록을 찾았습니다.

거리            5.04 km
운동 시간       29:23
평균 페이스     5:49 /km
평균 케이던스   166 spm
평균 심박수     154 bpm

[ 맞아요 ]   [ 수정하기 ]
```

### 5.3 직접 입력

사용자가 최근 러닝 기록을 직접 입력한다.

#### 기본 입력 필드

**필수**

- 거리
- 운동 시간 또는 평균 페이스

**강력 권장**

- 평균 케이던스

**선택**

- 평균 심박수
- 러닝 날짜
- 고도/상승고도
- 러닝 유형

거리·시간·페이스처럼 서로 계산 가능한 값은 웹에서 자동 계산해 사용자의 입력 부담을 줄인다.

예:

- 거리 + 시간 → 평균 페이스 자동 계산
- 거리 + 평균 페이스 → 예상 시간 자동 계산

직접 입력도 기본적으로 **최근 5회 기록**을 받을 수 있게 구성한다. 데이터가 부족하면 1회 기록만으로도 분석을 진행하되 정확도가 낮을 수 있음을 안내한다.

## 6. 목표 페이스 입력

사용자는 자신이 유지하고 싶은 **목표 페이스**를 입력한다.

예:

```text
목표 페이스
5:30 /km
```

목표 페이스는 최근 러닝 기록과 함께 AI 분석의 핵심 입력이다.

## 7. 음악 취향 입력

러닝 목적뿐 아니라 사용자의 음악 취향을 함께 반영한다.

기본적으로 다음을 받을 수 있게 한다.

- 선호 장르
- 좋아하는 아티스트
- 선호하지 않는 장르
- 선호하지 않는 아티스트

초기 UI에서는 복잡한 음악 프로필을 만들기보다 빠르게 선택할 수 있는 간단한 입력으로 구성한다.

예:

```text
좋아하는 음악
[K-pop] [J-pop] [Rock] [Hip-hop] [EDM]

좋아하는 아티스트
[                       ]

추천에서 빼고 싶은 아티스트
[                       ]
```

## 8. OpenAI API의 역할

러닝 기록 분석과 최종 음악 추천 판단은 **OpenAI API**가 담당한다.

MVP는 **Responses API 기반**으로 설계한다. OpenAI Responses API는 이미지 입력, Web Search 도구, Structured Outputs를 지원하므로 스크린샷 분석·음악 탐색·구조화된 결과 반환을 하나의 AI 계층으로 설계할 수 있다.

### 8.1 러닝 기록 분석

AI는 다음을 분석한다.

- 최근 평균 페이스 및 변화 경향
- 평균 케이던스
- 페이스와 케이던스의 관계
- 페이스 변동성 / Pace Stability
- 심박 정보가 있을 경우 운동 강도 맥락
- 거리와 러닝 유형
- 목표 페이스와 현재 기록의 차이
- 목표 페이스에서 예상되는 적정 케이던스 범위
- 목표 페이스 유지에 적합할 가능성이 높은 음악 BPM 범위

### 8.2 음악 리듬 추천

AI는 단순히 `목표 페이스 = 특정 BPM`으로 계산하지 않는다.

초기 추천 로직은 다음 원칙을 사용한다.

1. 사용자의 최근 페이스-케이던스 관계를 우선 분석한다.
2. 목표 페이스에서 예상되는 케이던스를 범위로 추론한다.
3. 해당 케이던스와 가까운 **1:1 BPM 범위**를 기본 추천한다.
4. 두 걸음당 한 박자로 사용할 수 있는 **half-time BPM**도 후보에 포함한다.
5. 목표 페이스와의 오차뿐 아니라 Pace Stability를 중요하게 평가한다.

예:

```text
목표 페이스      5:30 /km
예상 케이던스    169–172 spm
추천 BPM         169–172 BPM
half-time        84.5–86 BPM
```

위 숫자는 사용자마다 달라진다.

### 8.3 음악 후보 탐색 및 사실 검증

LLM의 기억만으로 곡명과 BPM을 확정하지 않는다.

MVP에서는 **OpenAI Responses API의 Web Search**를 이용해 실제 곡 후보와 BPM 등 음악 메타데이터를 탐색·검증한다.

향후 트래픽과 일관성이 중요해지면 별도 음악 메타데이터 API/DB를 추가할 수 있다.

AI는 검색된 후보를 대상으로 다음 기준으로 최종 랭킹한다.

- 목표 리듬 적합도
- 사용자의 과거 페이스 안정성과의 적합도
- 사용자 음악 취향
- 운동에 적합한 에너지 특성

초기 추천 가중치:

- 목표 리듬 적합도: **40%**
- 과거 페이스 안정성: **30%**
- 음악 선호도: **20%**
- 운동 에너지 특성: **10%**

가중치는 실제 사용자 피드백과 실험 데이터를 통해 이후 조정할 수 있다.

## 9. 추천 결과

한 번의 추천에서 **10~20곡**을 제공한다.

각 추천곡에는 다음 정보를 표시한다.

- 앨범 아트
- 곡명
- 아티스트
- BPM
- Match Score
- 추천 이유

예:

```text
[Album Art]
SONG TITLE
Artist

170 BPM        96% MATCH

최근 기록에서 추정한 목표 케이던스와 가장 가까우며,
5:30/km 페이스 유지에 적합한 리듬 후보입니다.
```

음악은 STEPSYNC에서 재생하지 않는다. 사용자가 원하는 경우 Spotify / Apple Music / YouTube Music 등 외부 음악 서비스에서 해당 곡을 검색하거나 열 수 있도록 링크를 제공한다.

## 10. Pace Stability

STEPSYNC는 단순 평균 페이스보다 **목표 페이스를 얼마나 안정적으로 유지했는지**를 중요한 지표로 본다.

예를 들어 목표가 5:30/km일 때:

```text
A: 5:29 / 5:31 / 5:30 / 5:32
B: 5:10 / 5:48 / 5:22 / 5:42
```

평균이 비슷하더라도 A가 목표 유지에 더 적합한 러닝으로 평가된다.

따라서 추천 시스템의 기본 목적은 다음 두 가지다.

1. 목표 페이스와의 평균 오차를 줄인다.
2. 페이스 변동성을 줄인다.

향후 사용자가 추천 음악을 듣고 다시 러닝한 결과를 입력하면, 어떤 BPM·곡·음악 특성에서 Pace Stability가 좋아졌는지 학습해 개인화를 강화한다.

## 11. 데이터 처리 원칙

### 11.1 코드가 담당하는 부분

단순하고 결정적인 계산은 웹 애플리케이션 코드에서 처리한다.

- 거리 + 시간 → 평균 페이스
- 단위 변환
- 입력값 검증
- 누락값 검사
- 세 입력 방식의 데이터 정규화
- 구간별 통계 계산

### 11.2 AI가 담당하는 부분

- 러닝 패턴 해석
- 목표 페이스와 현재 상태의 관계 분석
- 적정 케이던스 및 BPM 범위 추론
- 음악 후보 평가
- 개인 취향 반영
- 최종 추천과 추천 이유 작성

즉 **계산 가능한 값은 코드가 계산하고, 맥락 해석과 추천 판단은 AI가 한다.**

- `integration`

## 13. OpenAI 출력 형식

프론트엔드에서 안정적으로 사용할 수 있도록 AI 결과는 자유 형식 텍스트가 아니라 **Structured Outputs / JSON Schema** 기반으로 받는다.

예:

```json
{
  "running_analysis": {
    "current_pace": "6:02",
    "current_cadence": 164,
```

## 15. 반응형 웹 요구사항

### 15.1 공통

PC와 모바일 모두에서 다음 기능을 동일하게 제공한다.

- 러닝 기록 입력 3방식
- 목표 페이스 입력
- 음악 취향 입력
- AI 분석 결과 확인
- 음악 추천 결과 확인

### 15.2 모바일

- Mobile-first
- 한 열 중심 세로 흐름
- 큰 터치 영역
- 큰 숫자 중심 UI
- 숫자 필드는 모바일 숫자 키패드를 적극 활용
- 스크린샷 업로드 접근성을 높인다.
- 추천곡은 세로 카드/목록 중심으로 표시한다.

### 15.3 PC

- 넓은 화면에서 러닝 기록과 목표/분석을 좌우로 배치한다.
- 여러 러닝 기록을 표 또는 밀도 높은 데이터 영역으로 비교할 수 있다.
- 추천곡의 부가 정보를 모바일보다 넓게 표시한다.

## 17. 향후 개인화

사용자가 추천받은 음악으로 러닝한 뒤 결과를 다시 입력하면 다음을 학습한다.

- 어떤 BPM에서 실제 케이던스가 어떻게 변하는지
- 어떤 곡에서 목표 페이스 오차가 줄었는지
- 어떤 음악에서 Pace Stability가 좋아졌는지
- 어떤 장르/리듬 특성이 사용자에게 잘 맞는지

이를 통해 장기적으로:

> **“당신은 169~171 BPM의 일정한 비트에서 5:30/km를 가장 안정적으로 유지하는 경향이 있습니다.”**

같은 개인화된 설명을 제공한다.

## 18. 기술 원칙

- OpenAI API 키는 브라우저에 노출하지 않고 서버에서 관리한다.
- 프론트엔드가 OpenAI API를 직접 호출하지 않는다.
- 사용자 업로드 이미지와 러닝 데이터는 필요한 범위만 서버로 전달한다.
- AI 결과는 JSON Schema로 검증한다.
- 곡의 BPM 등 사실 데이터는 모델의 기억만 믿지 않고 검색 결과로 검증한다.
