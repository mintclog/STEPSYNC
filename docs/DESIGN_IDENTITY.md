# STEPSYNC 디자인 정체성

> **Sport Tech × Music Editorial**
>
> **Running science, presented like music.**

러닝 데이터의 명료함과 음악의 리듬감을 하나의 시각 언어로 결합한다.

---

## 1. 문서 목적과 결정 원칙

이 문서는 STEPSYNC의 브랜드 및 UI 디자인 정체성을 정의한다.

제품 문서와 동일하게 다음 원칙을 적용한다.

- 사용자가 직접 지정한 내용은 확정한다.
- 제안 후 사용자가 반박하거나 다른 방향을 지정하지 않은 내용도 확정한다.
- 최신 사용자 결정이 이전 제안보다 우선한다.
- 여러 대안 중 하나가 선택되지 않은 경우 첫 추천안을 기본안으로 사용한다.

## 4. 전체 시각 원칙

### 4.1 밝고 활동적인 기본 인상

다크모드 중심보다 **밝은 배경 + 강한 포인트 컬러**를 기본 디자인으로 한다.

러닝의 야외성·활동성을 살리고, 음악 서비스의 디지털 감각은 포인트 컬러와 앨범 아트로 표현한다.

### 4.2 숫자가 주인공

STEPSYNC에서 가장 중요한 시각 정보는 숫자다.

```text
5:30 /km
170 BPM
166 spm
96% MATCH
```

따라서 페이스·BPM·케이던스 같은 숫자를 단순 데이터가 아니라 **브랜드의 그래픽 요소**로 사용한다.

- 숫자는 크게
- 단위는 작게
- 핵심 결과는 한눈에 들어오게

### 4.3 음악은 Waveform보다 Beat

서비스의 핵심은 음원 재생이나 오디오 편집이 아니라 **러닝 리듬과 음악 비트의 관계**다.

따라서 waveform보다 다음과 같은 반복 요소를 그래픽 모티프로 사용한다.

```text
●    ●    ●    ●

│  │  │  │  │  │
```

- 일정한 beat grid
- cadence tick
- 반복 간격
- 리듬에 맞춘 숫자/구분선

### 4.4 카드 남용 금지

일반적인 SaaS처럼 모든 정보를 작은 카드 안에 넣지 않는다.

대신:

- 큰 섹션
- 굵은 숫자
- 명확한 구분선
- 충분한 여백

을 중심으로 구성한다.

카드는 독립성이 강한 요소에만 사용한다.

- 추천곡
- 개별 러닝 기록
- 기록 입력 방식 선택

### 4.5 AI는 기술이지 시각적 주인공이 아님

다음과 같은 전형적인 AI UI를 피한다.

- 보라/파랑 AI 그라데이션
- 과도한 glow
- sparkle 아이콘 남용
- 챗봇 캐릭터 중심 UI

OpenAI API는 제품 기술이며, STEPSYNC의 시각적 주인공은 **러닝과 음악**이다.

## 5. 컬러 시스템

### 5.1 기본 팔레트

**Warm White + Near Black + Electric Lime**

기본값:

| 역할 | 컬러 | 기본 HEX |
|---|---|---|
| Background | Warm White | `#F7F7F4` |
| Primary Text | Near Black | `#171717` |
| Accent | Electric Lime | `#C7F000` |

실제 구현 시 접근성 대비를 확인한 뒤 미세 조정할 수 있지만, 색상 정체성은 유지한다.

### 5.2 색상 비중

기본 비중:

- Neutral / Background / Text: **약 80%**
- Accent: **약 15%**
- Album Art 및 음악 콘텐츠 컬러: **약 5%**

정확한 면적 비율이 아니라 화면의 시각적 우선순위를 위한 가이드다.

### 5.3 Electric Lime 사용처

포인트 컬러는 제한적으로 사용한다.

- 주요 CTA
- 선택 상태
- 활성 상태
- 중요한 추천 수치
- focus / interaction state

UI 전체를 라임색으로 채우지 않는다.

### 5.4 피해야 할 컬러 사용

- 다수의 네온 컬러 동시 사용
- 화려한 배경 그라데이션
- 앨범 아트와 경쟁하는 강한 배경
- 모든 정보에 포인트 컬러 적용

## 6. 타이포그래피

### 6.1 기본 방향

- 현대적인 sans-serif
- 숫자 가독성이 뛰어나야 함
- 한글 / 영문 / 숫자가 자연스럽게 섞여야 함
- 과도하게 장식적인 폰트는 사용하지 않음

최종 폰트 패밀리는 구현 단계에서 선택한다.

### 6.2 숫자 위계

#### Hero Number

```text
5:30
/km
```

사용처:

- 현재 페이스
- 목표 페이스
- 추천 BPM
- 핵심 Match Score

#### Supporting Data

```text
166 spm
154 bpm
```

Hero Number보다 작고 절제되게 표현한다.

#### Explanation

AI 분석 이유나 추천 이유는 일반 본문 크기로 표현한다.

## 7. 레이아웃

### 7.1 큰 섹션 중심

기본 예:

```text
YOUR RUN

5:52 /km
166 spm

────────────────────

TARGET

5:30 /km

────────────────────

AI ANALYSIS

169 — 172 BPM
```

### 7.2 PC 레이아웃

넓은 화면에서는 러닝 데이터와 목표/설정을 병렬로 보여준다.

```text
[ 최근 러닝 기록 ]   [ 목표 페이스 / 음악 취향 ]

[              AI 러닝 분석 결과               ]

[                추천 음악 목록                ]
```

- 여러 러닝 기록을 표나 비교 영역으로 표현 가능
- 분석 정보를 모바일보다 더 밀도 있게 보여줌
- 추천곡 추가 정보를 한 화면에 더 많이 표시

### 7.3 모바일 레이아웃

한 열 중심의 세로 흐름을 사용한다.

```text
[최근 러닝 기록]
        ↓
[목표 페이스]
        ↓
[음악 취향]
        ↓
[AI 분석 결과]
        ↓
[추천 음악]
```

- 큰 숫자
- 큰 터치 타깃
- 충분한 여백
- 추천곡은 세로 카드/목록
- 스크린샷 업로드가 쉽게 보여야 함

### 7.4 Mobile-first

CSS와 컴포넌트 설계는 **Mobile-first responsive design**을 기본으로 하고, 넓은 화면에서 레이아웃을 확장한다.

정확한 breakpoint 수치는 구현 단계에서 정한다.

- 명확한 텍스트

예:

```text

```

### 8.3 아이콘

- 단순한 line icon
- 일관된 stroke
- 실제 제품 UI에서 emoji 사용을 중심 표현으로 삼지 않음

## 9. 러닝 기록 입력 화면

세 입력 방식을 명확하게 보여준다.

```text
러닝 앱 연결하기
가장 간편해요

기록 화면 올리기
Samsung Health 등 지원

직접 입력할게요 →
```

### 모바일

- 스크린샷 업로드를 접근하기 쉽게 배치
- 숫자 입력은 모바일 숫자 키패드에 맞게 구현
- 직접 입력은 세로 폼

### PC

- 세 입력 방식을 더 넓은 선택 영역으로 표현 가능
- 최근 기록이 이미 있다면 우측 또는 하단에 함께 표시

## 10. 목표 페이스 화면

목표 페이스는 서비스의 핵심 입력이므로 가장 크게 표현한다.

```text
어느 페이스로 달리고 싶나요?

      5 : 30
        /km

[ 내 러닝 음악 찾기 → ]
```

숫자와 CTA 사이의 정보 밀도를 낮게 유지한다.

---

## 11. AI 분석 화면

AI를 채팅 인터페이스처럼 표현하지 않는다.

**데이터 → 해석 → 추천 리듬** 순서로 보여준다.

예:

```text
YOUR RUN
5:52 /km
166 spm

TARGET
5:30 /km

당신은 속도가 증가할 때
케이던스가 함께 증가하는 경향이 있습니다.

RECOMMENDED RHYTHM
169 — 172 BPM
```

PC에서는 간단한 추세 그래프를 추가할 수 있다.

---

## 12. 음악 추천 화면

분석 영역보다 음악적인 감성을 조금 더 강하게 사용한다.

각 추천곡은 다음 정보를 포함한다.

- 앨범 아트
- 곡명
- 아티스트
- BPM
- Match Score
- 짧은 추천 이유

예:

```text
[Album]
SONG TITLE
Artist

170 BPM        96% MATCH

목표 케이던스와 가장 가까운 리듬 후보
```

앨범 아트가 화면에 자연스러운 색을 제공하므로 주변 UI는 절제한다.

음악 플레이어처럼 play/pause, progress bar를 강조하지 않는다.

## 13. 데이터 시각화

PC에서는 페이스와 케이던스 관계를 간결하게 보여줄 수 있다.

예:

```text
6:00 ──●
5:50 ─────●
5:40 ─────────●
5:30 ────────────── TARGET
```

원칙:

- 데이터 시각화는 분석 이해를 돕는 수준으로 제한
- 복잡한 전문 러닝 대시보드가 되지 않도록 함
- 모바일에서는 핵심 숫자와 짧은 요약을 우선

---

## 14. Beat / Cadence 모션

모션은 장식이 아니라 리듬의 개념을 강화하는 데 사용한다.

사용 가능:

- 분석 중 짧은 beat pulse
- 숫자가 최종 값으로 수렴하는 transition
- 추천 BPM 결과가 나타나는 짧은 리듬 애니메이션
- 선택 시 beat tick 반응

피해야 할 것:

- 계속 움직이는 배경
- 과도한 particle
- 강한 glow
- 의미 없는 parallax
- 긴 로딩 연출

`prefers-reduced-motion` 환경에서는 정적인 상태를 제공한다.

## 15. 로고 방향

브랜드명은 **STEPSYNC** 대문자 워드마크를 기본으로 한다.

로고 개념:

- cadence와 beat의 결합
- 서로 다른 두 리듬이 정렬되는 모습
- `STEP`과 `SYNC`의 타이포그래피 차이를 활용
- 발걸음과 음악이 동기화되는 개념

피해야 할 것:

- 흔한 달리는 사람 실루엣
- 운동화 + 음표의 직접적인 조합
- AI sparkle 중심 로고

최종 로고 그래픽 자체는 별도 제작 단계에서 확정한다.
